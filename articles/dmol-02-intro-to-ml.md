## データ: AqSolDB (Delaney 溶解度データセット)

dmol Ch2で使うデータは**AqSolDB** ([Scientific Data, doi:10.1038/s41597-019-0151-1](https://doi.org/10.1038/s41597-019-0151-1)) という水溶解度データセット。Delaney (2004) を含む9つの公開データを統合・整備したもので、**9982化合物** を収録。本家リポジトリは [mcsorkun/AqSolDB](https://github.com/mcsorkun/AqSolDB)。

中身は **9982 行 × 26 列** で、列は3グループに分かれる:

| 区分 | 列数 | 中身 (一例) | 役割 |
|---|---|---|---|
| A. 同定情報 | 5 | `ID`, `Name`, `SMILES`, `InChI`, `InChIKey` | 「どの分子か」を追跡するキー (モデルには使わない) |
| B. ラベル + 品質メタ | 4 | `Solubility`, `SD`, `Ocurrences`, `Group` | **`Solubility` が目的変数**、残りはデータ品質情報 |
| C. RDKit 記述子 | 17 | `MolWt`, `MolLogP`, `TPSA`, `BertzCT`, ... | **17列の特徴量** |


1. 予測したい値 `Solubility` は「水への溶けやすさ」を対数で表した数字。生の値だと「一番溶けない分子」と「一番溶ける分子」で 約 10¹⁵ 倍 (= 千兆倍) もの差がある。そのままでは数値として扱いにくいので、log を取る。
2. モデルに入れる17個の特徴量 は、列ごとに桁数も単位もバラバラ。例えば `BertzCT` (構造の複雑さ指標) は 0〜20720、`BalabanJ` (トポロジ指数) は 0〜7。標準化が必要。


# Chapter 2: Introduction to Machine Learning

## 1. The Ingredients — 機械学習の3つの材料


- 特徴量 (Features) : 分子1個あたり d 個の数値、それが n 個分 — 今回は RDKit 記述子17個 × 9982分子 = `(9982, 17)`
- 予測したい値 (Labels) : n 個の数値 (回帰なら実数、分類なら整数) — 今回は各分子の LogS、9982個
- モデル (Model) : 特徴量を入れたら予測値を返す関数 — 今回は「17個の数値 → LogS」を返す ものを学習で決める

## 2. データ準備


1. 26列のうち  17列を 特徴量として抜き出す
2. `Solubility` 列を 予測したい値に取る

ラベルの分布をで見ると、平均 -2.89 / std 2.37 /だけど 範囲 -13.17 〜 +2.14で左に長く尾を引く (= 極端に溶けない分子が少数いる)。


## 3. 線形モデルを書く (JAX)

モデルは 線形回帰。17個の特徴量に重み を掛けて足し、バイアスを加える。

予測の誤差を MSE (平均二乗誤差)

## 4. 勾配降下

勾配降下法という手法を使う。

「いま予測がどれくらいズレているか (= Loss)」を測り、Loss が小さくなる方向に パラメータを 少しずつ動かすことを繰り返す。


生の 特徴量のまま (= 標準化なし)、10 ステップだけ回してみると、結果は final loss = 10832 という異常に大きい数字になる。

もし学習を全くせず「予測値を常にラベルの平均 (-2.9) に固定」しただけでも loss は 5〜6 程度で収まるはず。それが 10832 ということは、学習が全く機能していないことになる。

### なぜこんなに大きいのか

理由は2つ:

1. 学習率 η が小さすぎる (1e-6) のでほとんど進んでいない (10ステップしか回していない)
2. 特徴量 のスケールが揃っていない ので、勾配の各成分の大きさが桁違いになる

2については`BertzCT` は範囲 0〜20720、`BalabanJ` は 0〜7。同じ重み更新式で扱うと、`BertzCT` の方向にだけ巨大な勾配が乗って、他の特徴は無視されたまま進む。

これを解決するのが次節。

## 5. 小分け学習 + 標準化 — 両方揃って初めて効く

### 小分け学習

データ全体を一気に使うのではなく、32 件などの小さなまとまり (バッチ) に分けて、バッチごとに勾配計算 → パラメータ更新を繰り返す。

これだけで、「全データを1周」する間の パラメータ更新回数が 1 回 → 数百回 に増える。


```
バッチ無し (全データで1回):       小分け学習 (32件ずつ):
[9982件 全部] → 更新 1回         [   0〜  31] → 更新 1回目
                                 [  32〜  63] → 更新 2回目
                                 [  64〜  95] → 更新 3回目
                                       ...
                                 [9952〜9981] → 更新 312回目
  ↑ 1 epoch で 1 回しか動けない     ↑ 1 epoch で 312 回も動ける
```

### 標準化

各列について「平均を引いて標準偏差で割る」だけ。

「平均 0 を中心に、ばらつき 1 で広がる」共通スケールに揃う。`BertzCT` の 0〜20720 も、`BalabanJ` の 0〜7 も、標準化後はだいたい -3 〜 +3 の範囲に収まる。

```
標準化前:                  標準化後:
BertzCT     : 0  20720    BertzCT     : -1.2  +2.8
MolWt       : 9   5299    MolWt       : -0.8  +1.5
BalabanJ    : 0   7.5     BalabanJ    : -2.1  +1.9
NumRings    : 0   36      NumRings    : -1.0  +3.2
   ↑ 列ごとに桁違い         ↑ 全列が同じレンジに揃う
```

### なぜ「小分け学習」と「標準化」はセットで効くのか

ためしに 標準化なしで小分け学習だけ入れる (η=1e-6, batch_size=32) と、loss は 1.05 × 10¹⁴ まで発散*する。

理由は 3 段階に分けて見るとはっきりする:

- バッチが小さいと → 勾配が「そのバッチ内のサンプルの偏り」に敏感に揺れる (例: たまたま `BertzCT` が大きい分子ばかりのバッチでは、その方向にだけ巨大な勾配が乗る)
- 標準化なし → 列ごとのスケール差がそのまま勾配の大きさに乗り、揺れが増幅されて発散


loss が 10832 → 3.7 まで一気に下がった** (約 3000 倍の改善)。相関係数 0.66。



## 6. 教師なし学習: k-means

ここから先は 教師なし (= ラベルなしで「似たデータをまとめる」)。

化学的な動機: 9982 分子を何種類かのグループ (例: 「水によく溶ける」「ほぼ溶けない」「特殊な構造をもつ」など) に自動で分けたい。ラベルを使わずに、特徴量 17 次元だけで グループ分けする。

標準化済みの 17 個の特徴量だけを使って、「4 グループに分けて」 (k=4) と指示して k-means を回してみる。

結果、9982 分子は 6012 / 3103 / 280 / 587 件 の 4 つのクラスタに分かれた。クラスタ内のまとまり具合を表す指標 (inertia) としては 94162

### クラスタサイズの偏り

`[6012, 3103, 280, 587]` ← 半分以上が 1 クラスタ (6012/9982 = 60%) に入っている。280 や 587 の小さなクラスタは外れ値的な特殊分子の塊 (例: 極端に大きい高分子、フッ素やヨウ素を大量に持つ分子など) になりがち。

## 7. Elbow plot — クラスタ数の選び方

k を増やすと inertia は単調に下がるが、「あるところを超えるとそれ以上 k を増やしても急に改善しない」 = エルボー が見えるはず。そこが「自然なクラスタ数」と解釈する。

dmol 本文と同じく 50 個に1個サブサンプリングして k=2..9 を回した実機の数値:

| k | 2 | 3 | 4 | 5 | 6 | 7 | 8 | 9 |
|---|---|---|---|---|---|---|---|---|
| inertia | 1864 | 1485 | 1285 | 1134 | 993 | 896 | 838 | 770 |

「ガクッと折れる」明確なエルボーは 無く、緩やかに下がる。dmol 本文も「3? 4? 6? 7?」 と曖昧で、結局 4 を選ぶ。

クラスタリングは複数の k で意味のある解釈が立つ方を選ぶ、というのが現実。教師あり学習 (回帰・分類) と違って正解ラベルが無いので、検証は人間の解釈に頼ることになる。
