# アイデア


前回 [Ch2: Introduction to ML](https://zenn.dev/nkwork9999/books/dmol-reading/viewer/intro-to-ml) で AqSolDB 全9982化合物 + 17記述子を Standardize + JAX で線形回帰し、相関係数 0.66 までは取れた。<br>
ただし その評価はランダムに split しただけで、過学習や化学固有の汚染を見ていない。Ch3 はその評価をやり直す章。

### 学ぶこと

- 過学習を 3つの要因 (ノイズ / 余剰特徴 / 訓練しすぎ) に分解する
- テスト誤差を ノイズ・偏り・分散 の3つに分解 (Bias-Variance) して、「どこまで改善できるか」の下限を式で理解する
- 重みの暴走で出る過学習を L2 正則化 (Ridge) で抑え、7次多項式の test loss が 1744 → 6.9 (約250倍改善)
- 1回の split を信用せず k-fold CV で平均
- ランダム評価では見えない誤差を LOCOCV (測定グループを丸ごと test に追い出す) で見る
- 分子骨格ごとに分けて評価する Scaffold split (Bemis-Murcko): random split より test MSE が **2.3倍** に跳ね上がる


# そもそも

dmol 本文は前章で出した「相関0.66」をいきなり信用せず、

1. そもそも 過学習 しているか?
2. 過学習を 偏り と 分散 で読み解けるか?
3. 化学データで ランダム分割 は信頼できるか?

の順で詰めていく。


# 試す

## §1. train25 + test25 で過学習を可視化

dmol が最初にやるのは「9982件あるのに、わざと 50 件だけ使う」。理由: 大量データだと overfit が起きにくく、学習曲線の test loss が綺麗に折れない。

ここで気にすべきコードは1点だけ — train の統計だけで test を標準化する:

```python
# ★ train の統計で test を標準化 (data leakage を避ける)
mean, std = train[feature_names].mean(), train[feature_names].std()
train[feature_names] = (train[feature_names] - mean) / std
test[feature_names]  = (test[feature_names]  - mean) / std
```

ここで test の mean/std を使ってしまうと、test の情報が前処理経由で train に漏れる (data leakage)。test は「未知データ」のフリをしたいので、train から決めた統計で test 側もスケール変換する。


実機の出力:

```
final train loss = 0.872
final test  loss = 1.310
min   test  loss = 1.077  at step 782
```

学習を続けると 訓練データの誤差はずっと下がり続ける (モデルが訓練データを覚え込んでいく)。一方、まだ見せていないテストデータの誤差 は最初は一緒に下がるが、ステップ782を境に逆に上がり始める。この「学習を続けるほど、未知データに対しては悪くなる」のが過学習の典型的な姿。


ここから出る対策が 早期打ち切り (early stopping): 「テスト誤差が下げ止まった瞬間に学習を止める」と、一番予測の良いモデル (=ステップ782時点のモデル) が手に入る。


## §2. 合成多項式で「過学習の3要因」を切り分ける

合成データの強みは 「正解の関数」が分かっていること。何が過学習を引き起こすか、原因を1つずつ切り分けられる。

真の関数から 20 点サンプリング、両端 10 点を train、真ん中 10 点を test に (= 学習に使っていない領域を予測させる)。


- 正解と同じ特徴量を渡し、ラベルにノイズも無い (ベースライン): テスト誤差 0.0 → 完璧に正解を再現
- そこに、ラベルのノイズだけを足す: テスト誤差 22.7 → ノイズ分だけ悪化するが、これはデータに元から乗っているノイズなので避けようがない (まだ過学習ではない)

- さらに、特徴量を必要以上に増やす (3次で済むのに 0〜6次の 7個を渡す): 訓練誤差 1.7 / テスト誤差 1744 → 訓練データには綺麗に合うのに、未知のテストでは1000倍悪化 = これが過学習

合成データで切り分けたから因果を断言できる。実データだとこの3つが交絡しまくって、何が原因か見えなくなる。

## §3. L2 正則化 (Ridge) で 1744 → 6.9 に下げる

§2 で見た「重みが暴走してテスト誤差 1744」を抑える定番が L2 正則化 (= Ridge 回帰)。仕組みは「重みが大きいほど追加で罰金を取る」だけ。モデルは罰金とのバランスを取って自然に重みを小さく保つ。

罰金の強さをツマミ λ で振った両端:

- λ=0 (罰金なし、普通の最小二乗): 訓練誤差 1.7 / テスト誤差 1744 / 重みの大きさ 73.9 → 過学習しっぱなし
- λ=10 (強めの罰金): 訓練誤差 11.3 / テスト誤差 6.9 / 重みの大きさ 0.9 → テスト誤差が約250倍改善

訓練誤差は 1.7 → 11 と悪化しているのに、テスト誤差は 1744 → 6.9。「訓練データへの当てはまりを少し犠牲にして、未知データへの予測を大きく良くする」のがトレードオフの本質。

補足: L1 (Lasso) は重みの絶対値で罰金するバリエーション。一部の重みが厳密に 0 になる (特徴選択効果)。予測精度なら L2、特徴選択なら L1、で使い分ける。

## §4. k-fold CV: 全データでは安定、N=25 では崩壊

1回 split のテスト誤差には「たまたま」が混ざる: test に難しい分子ばかり集まれば誤差が大きく、簡単なのばかりなら小さく出る。データを k 等分して、順に1つを test・残り全部で学習、を k 回繰り返して誤差を平均して解消する。

このとき、k 回の誤差がどれくらいバラけたか (ばらつき = std) も一緒に取れる。バラけが平均より小さければ「どのフォールドでも似た結果」= 平均値は信頼できる。平均と同じくらい大きければ「フォールド毎に全然違う」= 平均はあてにならない、というシグナル。

§1 と同じ小データ (N=25) と全データ (9982件) で比較:

- 全データ・k=5: 平均 MSE 2.79、std 0.20 → std が平均より遥かに小さい = 安定 (k=10, 20 でもほぼ同じ数字が出る)
- N=25・k=5: 平均 MSE 51.3、std 49.6 → std が平均並み = フォールド毎に大荒れで、平均が信用できない
- N=25・k=25 (LOOCV、1点ずつ test に回す極端版): MSE 24.3、std 61.7 → 余計に荒れる

大量データなら k を変えても結果はほぼ動かないが、小データだと MSE が 13〜51 まで暴れる。dmol が「小データほど k-foldが要る」と強調する理由がここで一目で出る。

## §5. LOCOCV: 測定グループを丸ごと test に追い出すと?

AqSolDB の Group 列 (G1〜G5、ソース数と SD で品質ランク付け、Ch2 で説明) は、別々の測定元・別々の品質特性を持つ。LOCOCV = 1グループまるごとを test に追い出して、残りで学習する。

各グループを test に追い出したときのテスト誤差:

- G1 (単一ソース、最大派閥、7746件): 3.23
- G2 (2ソース・食い違い大、235件): 6.37
- G3 (2ソース・一致、1182件): 2.08
- G4 (3+ソース・食い違い大、183件): 6.33
- G5 (3+ソース・一致、最高品質、636件): 2.56
- 平均: 4.11

普通の k=5 CV (= 2.79) と比べると LOCOCV のほうが 1.47 倍悪い。「測定グループ別に偏りがあって、片方を test に追い出すと random CV では見えない誤差が出る」ということ。

特に G2 と G4 (もともと値が食い違っているグループ) だけテスト誤差が 2倍以上跳ねていて、データ品質の偏りがそのままテスト誤差に出ているのがわかる。

## §6. Scaffold Split

化学データでは「近い分子 (= 同じ骨格で置換基だけ違う) が train と test に混在しがち」で、モデルは「骨格を覚えればよい」状態に逃げてしまう。なので ランダム分割 は化学的に意味のある test 集合を作れない。

代わりに使うのが Bemis-Murcko の「骨格抽出」。これは分子から置換基 (側鎖) を全部削ぎ落として、環と環同士をつなぐ部分だけを残す方法。例えば メチルベンゼン (c1ccccc1-CH3) と ベンジルアルコール (c1ccccc1-CH2-OH) は、骨格としてはどちらも c1ccccc1 (= ベンゼン) に揃う。

この骨格で分子をグルーピングし、希少な骨格をまとめて test に追い出す。<br>train には見慣れた骨格、test には未知の骨格だけが入る形になり、「新規骨格でもどこまで当てられるか」という化学のリアルな課題を模した評価ができる。これが MoleculeNet 系で標準の scaffold split。

鍵は「希少骨格から順に test に追加、test が全体の 20% に達したら止める」というロジック:

```python
from rdkit.Chem.Scaffolds import MurckoScaffold
# MurckoScaffoldSmiles: 分子から側鎖を削いで「骨格だけの SMILES」を返す RDKit 関数
sc = MurckoScaffold.MurckoScaffoldSmiles(mol=mol, includeChirality=False)
# 希少骨格から順に test に追加、20% に達したら止める
```

結果:

- 一意な骨格数: 1948
- scaffold split: train 7986 / test 1996、テスト誤差 6.31
- ランダム分割 (同サイズで比較): テスト誤差 2.74
- 比率: scaffold は ランダムの 2.31倍悪い

Ch2 で出た「相関0.66」はランダム分割だから取れた数字で、scaffold split に切り替えると評価は一気に厳しくなる。

骨格の分布が物語的でもある: train 側にはベンゼン (1753件)・脂肪族鎖 (2940件)・ビフェニル (219件) のような「お馴染み骨格」が集まり、test 側にはフェナントリジノンやジエポキシのような「滅多に出ない骨格」が回される。つまり scaffold split は「ベンゼン由来の常識を覚えたモデルが、見たことない骨格でどこまでやれるか」を試している。化学のリアルな課題 (新規骨格でのスクリーニング) を模した評価。


# 雑感

- Scaffold split で 2.3倍悪化、これは知らないと事故る数字。「ランダム分割で相関 0.66 取れました」と論文で報告されていても、見たことのない骨格の分子に対しては予測誤差が2倍以上に悪化しうる、ということ。random split のスコアだけ載せている論文を読むと、ぐっと警戒したくなる
- L2 (Ridge) の嬉しいところは「答えが式で一発で出る」こと (= 閉形式解)。学習率を調整して何千ステップも回す必要がなく、numpy の `lstsq` を1行呼ぶだけで最適な重みが直接返ってくる。
