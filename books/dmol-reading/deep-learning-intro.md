# アイデア

前回 [Ch5: Kernel Learning](https://dmol.pub/ml/kernel.html) では、分子を「学習データ中の各点との距離」として表す見方を扱った。今回から Deep Learning で AqSolDB の溶解度予測に入る。ただし、これまで使ってきた JAX ではなく PyTorch を使う。

やること自体はかなり素直である。AqSolDB に入っている分子記述子を、平均0・標準偏差1になるようにそろえ (標準化し)、その表形式のデータを小さなかたまり (batch) に分けて、少しずつモデルに流し込んで学習させる。

Ch2 の線形回帰では、標準化した分子記述子に重みをかけて足し合わせ、そこに下駄 (bias) を足すだけで、溶解度 `y` を直接予測していた。つまり、入力の特徴量から出力までの間に、特徴量を作り直す段階がなかった。

Ch6 で新しく増えるのは、入力と出力のあいだに「一度別の形に作り直す」ステップである。順番に追うとこうなる。

1. まず、17個くらいの分子記述子を受け取り、それをいったん32個の数のまとまり (32次元の表現) に変換する。ここではまだ「溶解度」を出しているのではなく、計算に使いやすい途中データを作っているだけである。
2. 次に、その32個の数を -1〜1 のあいだに曲げて押し込む。これがあることで、「ただの足し算・掛け算の繰り返し」では作れない、曲がった (非線形な) 関係を表せるようになる。
3. 最後に、その32個の数から溶解度の予測値を1つだけ計算して出す。

つまり「記述子 → いったん32次元に作り直す → 曲げる → 溶解度を1つ出す」という流れである。線形回帰との違いは、途中に「作り直す段階」が1つ挟まっただけ、と思えばよい。

この「途中で作られる表現」を、神経の比喩としてではなく「入力特徴量を、予測しやすい形にいったん作り直したもの」として見ると、この章はかなり読みやすくなる。

### 学ぶこと

- ディープラーニングを「魔法」ではなく、ニューラルネットを使った機械学習の一カテゴリとして位置づける
- 全結合層 (dense layer) が、入力の数すべてを出力の数すべてにつなぐ行列のかけ算であること
- 活性化関数を1つ挟むだけで、線形変換を重ねても線形のままだったモデルが、曲がった関係を表せる非線形モデルに変わること
- 分子記述子を一度「途中の表現」に作り直してから溶解度を予測する、という線形回帰との違い
- PyTorch で学習ループを組む流れ: データをテンソルにし、小分け (batch) に取り出し、モデル・損失・最適化をつないで重みを更新する
- 学習中と評価中でモデルの振る舞いを切り替える理由 (training mode / eval mode と、勾配計算を止める指定)
- 標準化やデータ分割といった評価設計の注意点は、ディープラーニングに移っても消えないこと

# Deep Learningをどう見るか

dmol の導入は、Deep Learning を AI の魔法としてではなく、機械学習の一カテゴリとして置いている。広い順に並べると、AI の中に機械学習があり、その中にディープラーニングがあり、さらにその中に回帰や分類のためのニューラルネットがある、という入れ子の関係になる。

ニューラルネットは、実装上はただの行列とベクトルの計算である。入力に行列をかけ、下駄 (bias) を足し、最後に「曲げる関数 (活性化関数)」を1つ通す。この「かけて、足して、曲げる」のひとかたまりを何層か重ねるだけである。

分子記述子のような手作りの特徴量を、そのまま回帰にかけるのではなく、モデルの内部でいったん別の表現へ作り直してから予測する。ここが Ch2 の線形回帰との一番の違いになる。

# AqSolDBをもう一度使う

データは、これまでと同じ curated solubility dataset (AqSolDB) を使う。分子量 (MolWt) より右の列が、回帰に使う分子記述子である。

特徴量は標準化する。各記述子を、平均0・標準偏差1にそろえる操作で、桁の大きい記述子 (分子量など) が学習を支配してしまうのを防ぐ。

ここで1つ注意点がある。これまでの Ch3 では、test の情報を train に漏らさないように、train だけで計算した平均・標準偏差を使って test も標準化していた。一方、今回の notebook では、説明を簡単にするために全データで標準化してから train/test に分けている。

- notebook: 全体像をつかむのを優先し、全データで標準化してから train/test に分ける
- 実務: train で平均・標準偏差を計算し、test にはその train の値を当てて標準化する

記事としては、この違いは明記しておきたい。Deep Learning に入っても、評価設計の罠 (data leakage) は消えない。

# TensorとDataLoader

PyTorch では、NumPy の配列をそのまま学習に使うのではなく、まず `torch.Tensor` という PyTorch 専用の入れ物に変換する。これが GPU に載せたり、勾配を自動で追跡したりするための土台になる。

このとき、正解ラベルである溶解度の側は、形を「縦1列」にそろえておく。モデルの出力が「バッチの件数 × 1」という形で出てくるので、ラベルも同じ形に合わせておかないと比較できないためである。

次に train/test に分けたら、DataLoader を用意する。これは、ひとことで言えば「データを学習に流し込む係」である。手元の全データを渡しておくと、学習のときに自動でいい感じに小分けして、順番に手渡してくれる。

具体的には、こんなことをまとめて引き受けてくれる。

- データを batch (小さなかたまり) に切り分けてくれる。全部を一度に流すのではなく、たとえば16件ずつ渡してくれるので、メモリにやさしく学習も安定する
- train のときは毎回順番をシャッフルしてくれる。データが種類ごとに並んでいても、偏った学習にならずに済む
- ループを回すたびに「入力のかたまりと、対応する正解のかたまり」をワンセットで手渡してくれる
- そのかたまりを GPU に載せて計算する、という流れの入口にもなる

イメージとしては、全データを渡しておくと、ループのたびに「16件ずつ・毎回シャッフルした状態で、入力と正解のペアを1組ずつ」配ってくれる、という感じである。

Ch2〜Ch5 では、この「16件ずつ切り出す」作業を自分で書くことが多かった。PyTorch では、そこを DataLoader にまるごと任せられる。

# モデル: Linear -> Tanh -> Linear

「モデルを作る」というと身構えてしまうが、ここでやることは実はとても単純である。用意した部品を、上から順番に3つ並べるだけ。それでこの章のニューラルネットは完成する。

並べる部品は次の3つである。

1. 全結合層 (Linear): 17個程度の分子記述子を、32個の数のまとまり (32次元の隠れ表現) へ広げる
2. 曲げる関数 (Tanh): その32個の数を -1〜1 のあいだに押し込んで、ぐにゃっと曲げる
3. 全結合層 (Linear): その32個の数から、溶解度の予測値を1つにまとめて出す

つまり「記述子 (17個くらい) → 32個に広げる → 曲げる → 1個に戻す」と数が変化していくだけのネットワークである。部品を順番に積み木のように積むだけ、と思えばよい。

ちょっとだけ補足しておきたいのが、真ん中の「曲げる関数」がなぜ要るのか、である。もし真ん中の曲げる工程を抜いて、全結合層をただ2回重ねただけにすると、見かけは2層でも、結局は「1回の全結合層」と同じものに化けてしまう。「行列を2回かけても、まとめれば1回かけるのと同じ」だからである。これだと、せっかく層を重ねても Ch2 の線形回帰と変わらない。

逆に言えば、間に「曲げる関数 (活性化関数)」を1つ挟むだけで、線形回帰では表せなかった曲がった関係まで表現できるようになる。地味な部品に見えて、ニューラルネットを「ただの線形回帰」から抜け出させている主役が、この曲げる工程である。

# 「曲がる」とはどういうことか

ここまで「曲げる」「曲がった関係」と何度か書いてきたので、その意味を少し補っておきたい。

線形回帰でできるのは、グラフに描くと「まっすぐな直線 (や平面)」の関係だけである。「入力が2倍になれば、出力もきっちり2倍」のような、一定のペースで増えたり減ったりする関係しか表せない。

ところが、現実のデータはそうとは限らない。たとえば溶解度なら、「ある範囲までは記述子が増えると溶けやすくなるが、あるところを超えると逆に頭打ちになる」といったことが起こりうる。こういう「途中でペースが変わる・向きが変わる」関係は、まっすぐな直線では追いきれない。グラフにすると線がカーブする。これが「曲がった関係」である。

「曲げる関数 (活性化関数)」は、まさにこのカーブを作るための部品である。直線しか描けなかった計算に「ここで折れる・ここで頭打ちにする」というクセを加える役割で、今回使う Tanh は、入力をどれだけ大きくしても出力を -1〜1 の範囲にやんわり押し込む (大きくなりすぎると寝てくる) という形で曲げてくれる。

この「曲げる工程」を、層と層のあいだに何度も挟むほど、モデルはより複雑なカーブを描けるようになる。ニューラルネットが線形回帰より表現力豊かなのは、突き詰めればこの一点に尽きる。

# 学習ループ

損失 (どれだけ予測が外れているか) は MSE (平均二乗誤差) で測り、その損失が小さくなる方向へ重みを少しずつ更新していく (SGD = 確率的勾配降下)という一般的なもの。

学習ループの中身は、batch (16件のかたまり) を1つ取り出すたびに、毎回この5ステップをくり返すだけである。やっていることは「予測してみる → どれだけ外したか測る → どう直せばいいか調べる → 少し直す」のサイクルで、人が問題を解いて答え合わせし、間違いを反省して直す、という流れにそのまま対応している。

1. **前回の反省メモを消す (zero_grad)**: PyTorch は「どう直すか」のメモ (勾配) を消さずにため込む性質がある。前のかたまりのメモが残ったままだと混ざってしまうので、まっさらにしてから始める
2. **予測してみる (forward)**: いまのモデルに入力 (分子記述子) を流し込んで、溶解度の予測値を出す。まずは答案を書いてみる段階
3. **どれだけ外したか測る (loss)**: その予測値と、本当の溶解度 (正解) を比べて、ズレの大きさを1つの数 (損失) にする。答え合わせをして失点を数える段階
4. **どう直せばいいか調べる (backward)**: その失点をもとに、「どの重みを、どちらの向きに動かせば失点が減るか」を全部の重みについて計算する。間違いの原因を1つずつ反省する段階
5. **少しだけ直す (step)**: 調べた向きへ、重みを少しだけ動かす。いきなり大きく直すと暴れるので、ちょっとずつ直して次のかたまりへ進む

JAX では「損失の勾配を作る関数」を自分で明示的に作っていた。PyTorch では、計算の流れを裏で自動的に記録しておき、`backward` で各重みの勾配をため、`step` で更新する、という分担になる。

最初の「前回の勾配を消す」を忘れると、勾配が前回の分とどんどん足され続けて、学習がおかしくなる。

# 評価: evalとno_grad

test データで予測するときは、学習時とは違うモードに切り替える。

学習が「問題を解いて反省して直す」だったのに対して、評価は「もう直さず、本番のテストを受けるだけ」である。この違いから、切り替えることが2つある。

1つは「評価モード (eval) に切り替える」こと。ニューラルネットの中には、学習中はわざと一部をサボらせる (dropout) など、学習のときと本番のときで動きを変える部品がある。評価モードにすると、そういう部品が一斉に「本番モード」に切り替わる。今回のモデルにはそうした部品は入っていないが、入っていても困らないよう、習慣として毎回書いておくと安全である。

もう1つは「もう直さないよ、と宣言する (勾配計算を止める)」こと。学習ループでいう4番目の「どう直せばいいか調べる」作業を、評価ではまるごと省く。どうせ重みを動かさないので調べるだけ無駄だし、止めておくとメモリも節約でき、結果を取り出すときの余計なトラブルも避けられる。

最後に、答え合わせをグラフで眺める。横軸に本当の溶解度 (実測値)、縦軸にモデルの予測値をとって点を打つと、ピタリ当たった点ほど「実測=予測」の対角線の上に乗る。点が対角線の近くに集まっているほど、よく当たっているということである。

# 線形回帰から何が変わったか

Ch2 の線形回帰は、「入力に重みをかけて足し、下駄を足す」だけのモデルだった。入力から出力まで一直線で、途中で何かを作り直す段階はなかった。

Ch6 のニューラルネットは、その手前に一段はさまる。まず入力をいったん隠れ表現 `h` に作り直し (かけて・足して・曲げる)、その `h` から溶解度を予測する。

差は、入力特徴量を一度 `h` に変換している点だけである。

この `h` は、データとして直接は観測されない。だから隠れ層 (hidden layer) と呼ばれる。だが、見えないから神秘的というわけではなく、単にモデルが内部で勝手に作った中間的な特徴量にすぎない。

分子データで考えると、元の特徴量は人間が設計した記述子である。

- 分子量 (MolWt)
- 脂溶性の指標 (LogP)
- 極性表面積 (TPSA)
- 水素結合のドナー数 / アクセプター数 (HBD / HBA)
- 環の数 (ring count)
- 部分構造の数 (fragment count)

ニューラルネットは、これらを組み合わせて、溶解度の予測に都合のよい内部表現を勝手に作り出す。

ただし、これは万能ではない。データが少ない、分割が悪い、特徴量が弱い、過学習している、といった問題はそのまま残る。Deep Learning にした瞬間に評価設計が不要になるわけではない。

# 雑感

Ch6 は、派手な deep learning というより「ここから PyTorch の世界へ入る」ための橋である。

モデルは小さい。全結合層・曲げる関数・全結合層、の3つだけ。だけど、ここに必要な部品は一通り出てくる。

- テンソル
- データセット
- データローダー
- デバイス (CPU / GPU)
- モデル
- 損失
- 最適化
- 学習ループ
- 評価ループ

これらを一度通すと、層を増やす、活性化関数を変える、正則化を入れる、そして GNN へ進む。全部、この小さな学習ループの延長線上にあるということらしい。
